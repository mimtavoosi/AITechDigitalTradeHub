# مستند کامل ماژول «نقشه راه یادگیری هوشمند» (AI Roadmap)

این مستند تمام اجزای سیستم پیشنهاد مسیر آموزشی با هوش مصنوعی را توضیح می‌دهد: معماری، قرارداد داده‌ها، نحوه استقرار روی سرورها، تنظیمات، امنیت بدون SSL و رفع اشکال.

---

## ۱. هدف

در صفحه عمومی آموزش (`/courses`) کاربر با پاسخ به چند سوال کوتاه و یک توضیح متنی آزاد، یک **نقشه راه یادگیری شخصی‌سازی‌شده** دریافت می‌کند. برخلاف نسخه قبلی که rule-based بود، حالا مدل زبانی **Gemma 4 26B** روی سرور GPU:

- همه دوره‌های منتشرشده سایت، دسته‌بندی‌ها و **سرفصل درس‌ها** را می‌بیند،
- پاسخ‌های پرسشنامه و توضیحات آزاد کاربر را تحلیل می‌کند،
- یک رودمپ چندمرحله‌ای (نودهای دارای ترتیب و وابستگی) برمی‌گرداند،
- و در هر نود، دوره‌هایی را پیشنهاد می‌دهد که سرفصل‌شان با همان مرحله هم‌خوانی دارد، همراه «دلیل انتخاب» و «درصد تطابق».

خروجی JSON ساخت‌یافته است و فرانت آن را به‌صورت تایم‌لاین گرافیکی رسم می‌کند.

---

## ۲. معماری کلی

```
┌─────────────────┐   HTTPS    ┌──────────────────────┐   HTTP (سرور به سرور)   ┌───────────────────────────┐
│  مرورگر کاربر    │ ─────────► │  بک‌اند دات‌نت (پلسک)  │ ──────────────────────► │ سرور GPU (37.255.232.255) │
│  Next.js فرانت  │            │  /api/education/     │      پورت 8181          │  Roadmap API (FastAPI)    │
│                 │            │  recommendations     │      X-Api-Key          │        │ 127.0.0.1:8000   │
└─────────────────┘            └──────────────────────┘                         │        ▼                  │
                                                                                │  vLLM + Gemma 4 26B       │
                                                                                └───────────────────────────┘
```

نکات کلیدی معماری:

- **فرانت هرگز مستقیم با سرور هوش مصنوعی حرف نمی‌زند.** همه‌چیز از بک‌اند دات‌نت عبور می‌کند؛ بنابراین کنترل دسترسی، لاگ و مدیریت خطا متمرکز است.
- **سرویس هوش مصنوعی stateless است**: به هیچ دیتابیسی وصل نیست. بک‌اند در هر درخواست، کاتالوگ دوره‌ها + پروفایل کاربر را یکجا می‌فرستد.
- اگر سرویس هوش مصنوعی در دسترس نباشد یا خروجی معتبر ندهد، کاربر پیام خطا می‌بیند (fallback حذف شده است).

## ۳. چرا بدون SSL کار می‌کند؟ (نکته مهم استقرار)

ارتباط بک‌اند (پلسک) با سرور هوش مصنوعی از نوع **سرور به سرور** است:

- محدودیت Mixed Content (بلاک شدن HTTP داخل صفحه HTTPS) **فقط مخصوص مرورگر** است. اینجا مرورگر کاربر فقط با سایت HTTPS شما کار دارد و هیچ‌وقت آدرس `37.255.232.255` را نمی‌بیند.
- `HttpClient` در دات‌نت هیچ مشکلی با فراخوانی آدرس `http://` ندارد؛ حتی اگر خود سایت روی HTTPS باشد. (`UseHttpsRedirection` فقط روی درخواست‌های **ورودی** اثر دارد، نه خروجی.)
- پس **نیازی به خرید یا نصب SSL روی سرور هوش مصنوعی نیست.** فقط دو کار امنیتی لازم است:

### امنیت جایگزین SSL (الزامی)

1. **کلید مشترک (API Key):** سرویس پایتون هدر `X-Api-Key` را چک می‌کند. یک رشته تصادفی طولانی بسازید:
   - روی سرور GPU در متغیر محیطی `ROADMAP_API_KEY` بگذارید.
   - همان مقدار را در `appsettings.json` بک‌اند در `AiRoadmap:ApiKey` بگذارید.
   - تا وقتی این دو ست نشده باشند، هرکسی که IP را بداند می‌تواند از GPU شما استفاده کند.
2. **فایروال روی سرور GPU:** پورت ۸۱۸۱ را فقط برای IP سرور پلسک باز کنید:

   ```powershell
   # ویندوز (سرور GPU) — IP_PLESK را با IP واقعی سرور بک‌اند عوض کنید
   New-NetFirewallRule -DisplayName "Roadmap API (backend only)" `
     -Direction Inbound -Protocol TCP -LocalPort 8181 `
     -RemoteAddress IP_PLESK -Action Allow
   New-NetFirewallRule -DisplayName "Roadmap API (block others)" `
     -Direction Inbound -Protocol TCP -LocalPort 8181 -Action Block
   ```

   ```bash
   # لینوکس (اگر سرویس داخل WSL/لینوکس expose می‌شود)
   ufw allow from IP_PLESK to any port 8181 proto tcp
   ufw deny 8181/tcp
   ```

3. پورت ۸۰۰۰ (vLLM) را **اصلاً از بیرون باز نکنید**؛ فقط `127.0.0.1` کافی است.

> اگر بعداً به production رفتید و خواستید رمزنگاری هم داشته باشید، بدون خرید SSL می‌توانید از Let's Encrypt رایگان (نیازمند یک ساب‌دامنه مثل `ai.aitechac.com`) یا تانل SSH/WireGuard بین دو سرور استفاده کنید. برای فاز توسعه فعلی لازم نیست.

### سمت پلسک چه چیزی لازم است؟

هیچ چیز خاصی. درخواست‌های **خروجی** (outbound) در پلسک به‌صورت پیش‌فرض آزادند. فقط:

- فایل `appsettings.json` کنار فایل‌های منتشرشده سایت باید بخش `AiRoadmap` را با `ApiKey` صحیح داشته باشد.
- اگر روی سرور پلسک فایروال خروجی سخت‌گیرانه فعال کرده‌اید (نادر است)، اجازه اتصال TCP خروجی به `37.255.232.255:8181` را بدهید.
- تست سریع از خود سرور پلسک (SSH یا از بخش Scheduled Tasks یک بار اجرا کنید):

  ```bash
  curl http://37.255.232.255:8181/health
  ```

  اگر JSON با `"status":"ok"` برگشت، مسیر ارتباطی برقرار است.

## ۴. اجزای سیستم و فایل‌ها

### ۴.۱. سرویس هوش مصنوعی — `gemma/roadmap_api/` (سرور GPU)

| فایل | نقش |
|---|---|
| `roadmap_server.py` | سرویس FastAPI روی پورت ۸۱۸۱؛ ساخت پرامپت، فراخوانی vLLM، اعتبارسنجی خروجی |
| `requirements.txt` | وابستگی‌ها: fastapi، uvicorn، requests، pydantic |
| `start_roadmap_api.ps1` | اجرای سرویس؛ اگر vLLM بالا نباشد اول آن را بالا می‌آورد و venv می‌سازد |
| `README.md` | راهنمای استقرار و قرارداد API |

منطق داخلی `roadmap_server.py`:

1. **احراز هویت:** اگر `ROADMAP_API_KEY` ست شده باشد، هدر `X-Api-Key` باید دقیقاً همان باشد؛ وگرنه `401`.
2. **فشرده‌سازی کاتالوگ:** متن‌های طولانی (توضیحات، خروجی یادگیری، سرفصل‌ها) بریده می‌شوند تا در کانتکست مدل جا شوند (حداکثر ۲۵ سرفصل و ۱۰ مهارت برای هر دوره).
3. **پرامپت فارسی:** نقش «مشاور آموزشی ارشد» با ۹ قاعده الزامی؛ از جمله: courseId جعلی نساز، دوره را فقط وقتی به نود وصل کن که سرفصلش با موضوع نود هم‌خوانی دارد، متن‌ها فارسی روان باشند.
4. **خروجی ساخت‌یافته:** درخواست با `response_format: json_schema` (قابلیت structured output در vLLM) ارسال می‌شود تا مدل مجبور به تولید JSON معتبر شود. اگر نسخه vLLM آن را نپذیرد (خطای 400)، بدون schema دوباره تلاش می‌شود و JSON از متن استخراج می‌شود.
5. **اعتبارسنجی (ضد توهم):**
   - `courseId`هایی که در کاتالوگ نیستند حذف می‌شوند.
   - `dependsOn`هایی که به نود موجودی اشاره نمی‌کنند حذف می‌شوند.
   - `matchScore` به بازه ۰ تا ۱۰۰ محدود می‌شود؛ نودها بر اساس `order` مرتب می‌شوند.
   - اگر کمتر از ۲ نود سالم بماند، پاسخ `502` است (بک‌اند همین را به کاربر برمی‌گرداند).
   - اگر `totalEstimatedWeeks` نیامده باشد از جمع هفته‌های نودهای غیراختیاری محاسبه می‌شود.

متغیرهای محیطی سرویس:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `GEMMA_URL` | `http://127.0.0.1:8000/v1/chat/completions` | آدرس vLLM |
| `GEMMA_MODEL` | `gemma4` | نام مدل سروشده |
| `GEMMA_TIMEOUT_SECONDS` | `180` | مهلت پاسخ مدل |
| `MAX_ROADMAP_TOKENS` | `3072` | سقف توکن خروجی |
| `ROADMAP_API_KEY` | خالی | کلید مشترک با بک‌اند (حتماً ست شود) |
| `LOG_LEVEL` | `INFO` | سطح لاگ |

جریان اکشن `Recommend`:

1. گزینه‌های انتخاب‌شده پرسشنامه به‌همراه متن سوال از دیتابیس خوانده می‌شوند و به جفت‌های «سوال/جواب» تبدیل می‌شوند.
2. همه دوره‌های `Published` با دسته، درس‌ها (سرفصل)، تگ‌های مهارتی و مدرس بارگذاری و به کاتالوگ تبدیل می‌شوند. (اگر هیچ دوره‌ای منتشر نشده باشد `502` با پیام مناسب برمی‌گردد.)
3. `AiRoadmapService.GenerateAsync` سرویس ۸۱۸۱ را صدا می‌زند (هدر `X-Api-Key` از تنظیمات).
4. `courseId`های خروجی به `CourseListItemResponse` کامل نگاشت می‌شوند تا فرانت همه اطلاعات کارت دوره (قیمت، مدرس، تعداد درس و...) را داشته باشد.
5. `RecommendedCourses` (حداکثر ۶ دوره یکتا با بالاترین تطابق) و زمان‌های رزرو مدرسِ اولین دوره هم ضمیمه می‌شود.
6. خطای سرویس ⇐ `502 Bad Gateway` با `ApiErrorResponse.ErrorMessage` فارسی؛ فرانت همان پیام را نشان می‌دهد.

تنظیمات `appsettings.json`:

```json
"AiRoadmap": {
  "Enable": true,
  "BaseUrl": "http://37.255.232.255:8181",
  "ApiKey": "",            // ⚠️ حتماً روی سرور مقداردهی شود (همان ROADMAP_API_KEY)
  "TimeoutSeconds": 180,
  "MaxNodes": 7,
  "MaxCoursesPerNode": 3
}
```

- `Enable: false` سرویس را موقتاً خاموش می‌کند (کاربر پیام «سرویس غیرفعال است» می‌بیند).
- `MaxNodes` و `MaxCoursesPerNode` به سرویس پایتون پاس می‌شوند و در پرامپت و اعتبارسنجی اعمال می‌شوند.

| فایل | تغییر |
|---|---|

رفتار UI:

- بعد از سوال‌های پرسشنامه، یک مرحله textarea اختیاری اضافه شده («درباره خودتان و هدفتان بیشتر بگویید» — حداکثر ۱۵۰۰ کاراکتر).
- حین تولید، پیام «هوش مصنوعی در حال تحلیل... ممکن است تا یک دقیقه طول بکشد» نمایش داده می‌شود.
- نتیجه: مودال عریض‌تر (`max-w-5xl`) با:
  - هدر عنوان/خلاصه مسیر + مدت کل به هفته،
  - **تایم‌لاین عمودی**: هر «فاز» یک دایره شماره‌دار با خط‌چین اتصال به فاز بعد؛ نودهای دارای `order` یکسان به‌صورت **موازی** (دو ستون) رندر می‌شوند،
  - کارت هر نود: عنوان، برچسب «اختیاری»، تخمین هفته، توضیح، پیش‌نیازها (از `dependsOn`)، چیپ مهارت‌ها و لیست دوره‌های پیشنهادی،
  - کارت هر دوره: نام، **نوار درصد تطابق**، دلیل انتخاب (نوشته مدل)، سطح و قیمت؛ کلیک ⇐ صفحه دوره،
  - بخش «توصیه‌های مسیر» (tips) و نوتیس زمان‌های رزرو مدرس،
  - دکمه‌های «پاسخ دوباره» و «شروع با اولین دوره پیشنهادی».
- در خطا، پیام برگشتی از سرور (مثلاً «ارتباط با سرویس هوشمند برقرار نشد») در همان مرحله آخر نمایش داده می‌شود و کاربر می‌تواند دوباره تلاش کند.

| وضعیت | کجا | معنی |
|---|---|---|
| `401` | سرویس AI | کلید `X-Api-Key` غلط است |
| `400` | سرویس AI | کاتالوگ خالی است |
| `502` از سرویس AI | سرویس AI | مدل جواب نداد / JSON خراب / کمتر از ۲ نود سالم |
| `502` از بک‌اند | بک‌اند | یکی از حالات بالا یا قطع ارتباط/تایم‌اوت؛ `errorMessage` فارسی برای نمایش به کاربر |

## ۶. راه‌اندازی گام‌به‌گام

### گام ۱ — سرور GPU (هوش مصنوعی)

1. پوشه `gemma/roadmap_api` را کنار پوشه مدل کپی کنید.
2. مطمئن شوید vLLM روی پورت ۸۰۰۰ فعال است (اسکریپت `run_gemma.ps1` موجود در پوشه gemma).
3. کلید بسازید و سرویس را اجرا کنید:

   ```powershell
   $env:ROADMAP_API_KEY = "kR9...یک-رشته-تصادفی-طولانی...x2"
   .\start_roadmap_api.ps1
   ```

   (این اسکریپت اگر لازم باشد venv می‌سازد، وابستگی‌ها را نصب می‌کند و uvicorn را روی `0.0.0.0:8181` بالا می‌آورد.)
4. قواعد فایروال بخش ۳ را اعمال کنید.
5. تست محلی: `curl http://127.0.0.1:8181/health`

### گام ۲ — سرور پلسک (بک‌اند)

1. در `appsettings.json` سایت منتشرشده، بخش `AiRoadmap` را کامل کنید (`ApiKey` = همان کلید گام ۱).
2. سایت را ری‌استارت کنید (Plesk ⇐ سایت ⇐ Restart App).
3. تست ارتباط از سرور پلسک: `curl http://37.255.232.255:8181/health`

### گام ۳ — تست end-to-end

1. صفحه `/courses` را باز کنید ⇐ «دریافت پیشنهاد مسیر».
2. سوال‌ها را جواب دهید، در مرحله آخر یک توضیح واقعی بنویسید و «ساخت نقشه راه» را بزنید.
3. تایم‌لاین باید ظرف حدود ۱۰ تا ۶۰ ثانیه (بسته به بار GPU) نمایش داده شود.
4. یا مستقیم با Swagger بک‌اند: `POST /api/education/recommendations` با بدنه نمونه بخش ۵.۱.

## ۷. رفع اشکال (Troubleshooting)

| علامت | علت محتمل | راه‌حل |
|---|---|---|
| فرانت: «ارتباط با سرویس هوشمند برقرار نشد» | سرویس ۸۱۸۱ خاموش است یا فایروال IP پلسک را نمی‌پذیرد | از سرور پلسک `curl .../health` بزنید؛ لاگ uvicorn را ببینید |
| فرانت: «سرویس هوشمند پاسخ معتبری برنگرداند» | خطای 401 (کلید ناهماهنگ) یا 502 داخلی سرویس | یکسان بودن `ApiKey` دو طرف را چک کنید؛ لاگ `roadmap-api` را ببینید |
| تایم‌اوت بعد از ۳ دقیقه | GPU مشغول است یا کاتالوگ خیلی بزرگ شده | `TimeoutSeconds` را بالا ببرید؛ تعداد/طول سرفصل‌ها در `compact_catalog` محدود است اما با رشد دوره‌ها می‌توان سقف‌ها را کمتر کرد |
| خطای «هنوز دوره منتشرشده‌ای وجود ندارد» | هیچ دوره‌ای در وضعیت Published نیست | حداقل یک دوره با درس منتشر کنید |
| مدل دوره بی‌ربط پیشنهاد می‌دهد | داده دوره ناقص است | `Description`، `LearningOutcomes` و عنوان درس‌ها (سرفصل‌ها) را برای دوره‌ها کامل کنید؛ کیفیت پیشنهاد مستقیماً به کیفیت این داده‌ها وابسته است |
| پاسخ همیشه 502 با «کمتر از ۲ نود» | خروجی مدل نامعتبر است (vLLM قدیمی بدون structured output) | لاگ سرویس را ببینید؛ ارتقای vLLM یا افزایش `MAX_ROADMAP_TOKENS` |
| می‌خواهم سرویس را موقتاً خاموش کنم | — | `AiRoadmap:Enable = false` در بک‌اند |

لاگ‌ها:

- **سرویس AI:** خروجی uvicorn — هر درخواست با شناسه ۸ کاراکتری، تعداد دوره‌ها، تعداد نودها و زمان تولید لاگ می‌شود.
- **بک‌اند:** Serilog — خطاهای فراخوانی با پیام `Roadmap API returned ...` یا `Roadmap API call failed` ثبت می‌شوند.

## ۸. ملاحظات و توسعه آینده

- **کیفیت داده = کیفیت رودمپ:** مهم‌ترین اهرم بهبود، کامل بودن سرفصل درس‌ها، توضیحات و مهارت‌های (SkillTags) هر دوره است.
- **کش:** فعلاً هر درخواست یک تولید کامل است. اگر بار زیاد شد می‌توان پاسخ را بر اساس هش (پاسخ‌ها + freeText + نسخه کاتالوگ) در سرویس پایتون یا بک‌اند کش کرد.
- **HTTPS در آینده:** با یک ساب‌دامنه رایگان + Let's Encrypt یا تانل WireGuard بین دو سرور، بدون هزینه قابل ارتقاست.
- **مانیتورینگ:** endpoint `GET /health` سرویس برای uptime-check مناسب است.
- فایل‌های مرتبط: [gemma/roadmap_api/README.md](gemma/roadmap_api/README.md) (استقرار سرویس AI) و [EDUCATION_MODULE_FA.md](EDUCATION_MODULE_FA.md) (کل ماژول آموزش).

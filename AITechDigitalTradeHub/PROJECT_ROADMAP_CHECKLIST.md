## تصمیم‌های فنی پایه

- [x] Backend: `ASP.NET Core Web API`
- [x] ORM: `Entity Framework Core`
- [x] Database: `SQL Server`
- [x] API Documentation: `Swagger / OpenAPI`
- [x] Authentication: `JWT + Refresh Token`
- [x] Authorization: Role/Permission based access control پایه
- [x] Authorization چندنقشی: هر کاربر می‌تواند چند نقش تاییدشده همزمان داشته باشد
- [ ] Realtime: `SignalR` برای اعلان، پیام‌رسانی و وضعیت پروژه در صورت نیاز
- [x] Frontend آینده: `Next.js + TypeScript + Tailwind CSS`
- [x] State/Data در فرانت آینده: `React Query` برای API و `Zustand` یا Context محدود برای state داخلی
- [x] جهت‌گیری صفحه اصلی از معرفی مارکت‌پلیس صرف به «شبکه تخصصی آی‌نت» با ۸ حوزه اصلی تغییر کرد: مشاوره، آموزش، پژوهش، پروژه، فرصت شغلی، سخت‌افزار و زیرساخت، سرمایه‌گذاری و تامین داده
- [x] معماری اطلاعات صفحات عمومی بر اساس حوزه‌ها نهایی شد؛ هدر و نوبار پایین لینک‌های سریع محدود دارند و همه حوزه‌ها در صفحه `/domains` تجمیع می‌شوند

## روش استفاده از این سند در هر جلسه توسعه

1. قبل از شروع، بخش «وضعیت فعلی کشف‌شده از کد» را با واقعیت پروژه تطبیق بده.
2. فقط یک فاز یا یک ماژول را برای همان جلسه انتخاب کن.
3. آیتم‌های انجام‌شده را از `[ ]` به `[x]` تغییر بده.
4. اگر تصمیم فنی گرفته شد، در بخش «تصمیم‌های فنی پایه» یا «موارد نیازمند تصمیم» ثبت کن.
5. اگر API جدید ساخته شد، در بخش APIهای MVP یا فاز مربوطه تیک بزن.
6. اگر چیزی از پروپوزال تغییر کرد، دلیل تغییر را پایین همین سند اضافه کن.
